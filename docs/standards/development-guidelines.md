## 2. 基础开发规则

### 2.1 文件位置必须写完整

所有文档、说明、提交说明、开发沟通里，只要引用文件、目录、配置、日志、命令结果，都必须写完整绝对路径。

正确示例：

```text
D:\zhizhouAi\myproject\prototypes\filepilot-tools\index.html
```

错误示例：

```text
prototypes\filepilot-tools\index.html
```

这样做是为了方便直接定位文件，不需要再自己拼路径。

### 2.2 缩进规则

新建或重写文件时统一使用 2 个空格缩进。

适用范围：

- `.html`
- `.css`
- `.js`
- `.ts`
- `.vue`
- `.json`
- `.md`

如果后续创建 `.vue` 文件，`<template>`、`<script>`、`<style>` 内部都使用 2 个空格缩进。

### 2.3 注释规则

注释可以比默认更详细，但不能写废话。

应该说明：

- 这段代码为什么这样做
- 在处理什么场景
- 要避免什么问题
- 哪些逻辑只是原型模拟，后面需要替换为真实能力

不应该说明：

- 语法本身是什么意思
- 每一行代码都做了什么
- 明显能从代码直接看出来的内容

正确示例：

```js
// 原型阶段只生成模拟压缩结果，先确认页面结构和结果区展示方式。
// 后续接入真实压缩逻辑时，只需要替换这里的数据来源，结果渲染结构保持不变。
```

## 3. 当前原型确认标准

### 3.1 原型定位

当前原型是一个全球工具类网站的第一版界面确认稿。

主要方向：

- 在线图片工具
- 在线 PDF 工具
- 浏览器本地处理
- 中英文双语
- 简洁专业的工具站界面

### 3.2 当前品牌名

暂用品牌名：

```text
FilePilot Tools
```

后续可以替换，但替换时要同时修改：

- 页面顶部 Logo 文案
- 首页标题或相关说明
- 页脚文案
- 浏览器标题
- 中英文语言包

### 3.3 当前原型页面范围

当前原型文件 `D:\zhizhouAi\myproject\prototypes\filepilot-tools\index.html` 包含五个页面状态：

- 首页
- 图片压缩页
- 图片转换页
- 图片转 PDF 页
- PDF 合并页

这是单文件原型，不是正式项目结构。

后续正式项目可以拆分为路由页面，但视觉、文案层级和交互顺序要先沿用当前原型。

## 4. UI 风格规范

### 4.1 总体风格

界面方向：

- 简洁
- 专业
- 直接
- 操作优先
- 不做复杂宣传页

页面重点必须放在：

- 选择文件
- 设置参数
- 开始处理
- 下载结果

不要把工具站做成营销官网。用户进入页面通常是为了马上处理文件，不是为了阅读长介绍。

### 4.2 颜色标准

当前原型主要颜色：

```text
页面背景：#f7f9fc
卡片背景：#ffffff
浅背景：#f1f5f9
主文字：#101827
次级文字：#667085
边框：#dce3ee
主色：#1d64f2
主色深色：#164fc4
主色浅色：#e8f0ff
成功色：#11845b
```

后续开发时可以微调，但不要改成大面积渐变、紫蓝炫光、过度装饰背景。

### 4.3 卡片规范

工具卡片用于展示单个工具入口。

卡片要求：

- 圆角保持在 `8px` 左右
- 边框清晰
- 背景白色
- 图标放在标题上方
- 标题直接写工具名称
- 描述只写一句，说明这个工具能做什么

不要在卡片里放太多说明，也不要嵌套卡片。

### 4.4 按钮规范

主要操作按钮：

- 使用蓝色背景
- 文案必须直接说明动作
- 例如 `Compress Images`、`选择图片`

次要按钮：

- 使用白底边框
- 用于非关键操作

不要出现含糊按钮文案，例如：

- `Start`
- `Go`
- `Submit`

除非上下文已经非常明确。

## 5. 图标规范

### 5.1 当前确认图标风格

当前用户最后确认的是轻线性图标版本。

对应文件：

- `D:\zhizhouAi\myproject\prototypes\filepilot-tools\index.html`

图标风格要求：

- 使用线性图标
- 图标放在浅色容器里
- 容器使用浅蓝底和细边框
- 线条不要太粗
- 图标要能看出工具功能
- 不再使用纯字母作为工具图标

当前工具图标语义：

| 工具 | 图标方向 |
| --- | --- |
| 图片压缩 | 图片框 + 缩小角标 |
| 图片转换 | 双向箭头 |
| 图片转 PDF | 文档 + 图片块 |
| PDF 合并 | 叠放文档 |
| PDF 拆分 | 文档中线拆分 |
| 图片尺寸调整 | 缩放箭头 + 中心方框 |
| 上传区域 | 图片上传图标 |

### 5.2 图标实现方式

当前原型使用内联 SVG。

原型阶段继续使用内联 SVG，原因：

- 单文件可直接打开
- 不依赖外部网络
- 不需要额外构建工具
- 方便快速调整图标

正式项目阶段可以改用图标库，但要保持视觉接近当前原型。

建议正式项目优先选择：

- `lucide-vue-next`

如果使用图标库，不要混用多个图标体系。

## 6. 多语言规范

### 6.1 首批语言

当前只支持两种语言：

- 英语：`en`
- 简体中文：`zh`

后续新增语言时，必须先保持中英文完整，再扩展其它语言。

### 6.2 文案维护方式

当前原型在 `D:\zhizhouAi\myproject\prototypes\filepilot-tools\index.html` 的 `translations` 对象里维护文案。

后续正式项目建议拆成：

```text
D:\zhizhouAi\myproject\locales\en.json
D:\zhizhouAi\myproject\locales\zh-CN.json
```

新增页面或组件时，不能只写英文硬编码。

必须同步处理：

- 英文文案
- 中文文案
- 动态结果文案
- 按钮文案
- 表格表头
- 错误提示

### 6.3 语言切换要求

语言切换必须影响：

- 导航
- 首页
- 工具卡片
- 工具详情页
- 表格
- 结果区
- 页脚
- 浏览器标题
- `html lang`

当前原型已经实现这些基础能力，正式项目要保留。

## 7. 工具页面规范

所有工具页都要保持统一结构。

页面顺序：

1. 顶部导航
2. 工具标题
3. 一句话说明
4. 文件选择区域
5. 本地处理说明
6. 参数设置区域
7. 处理按钮
8. 结果区域
9. 相关工具

这样做是为了降低用户学习成本。用户使用过一个工具后，进入另一个工具也能知道怎么操作。

## 8. 文件处理说明规范

当前产品核心卖点是：

```text
文件直接在浏览器中处理，不会上传到服务器。
```

英文：

```text
Files are processed directly in your browser and are not uploaded to our server.
```

这句话必须出现在每个支持本地处理的工具页里，并靠近文件选择区域。

注意：

- 如果某个工具后续需要上传到服务器处理，不能继续使用这句文案。
- 需要上传服务器的工具必须单独说明原因和文件保存策略。

## 9. 原型和正式功能边界

当前 `D:\zhizhouAi\myproject\prototypes\filepilot-tools\index.html` 是原型。

原型里可以使用模拟结果，但必须让代码注释写清楚：

- 当前只是模拟
- 真实逻辑后续在哪里替换
- UI 结构是否会保留

例如图片压缩页当前选择图片后显示模拟压缩结果，不代表已经实现真实压缩。

正式开发时，需要把模拟逻辑替换为真实能力。

## 11. 组件规范

### 11.1 ToolCard

用途：

- 首页和分类页展示工具入口

字段建议：

```ts
type ToolCardItem = {
  titleKey: string
  descriptionKey: string
  icon: string
  href: string
}
```

注意：

- 标题和描述使用语言 key，不直接写死文案
- 图标使用统一的图标组件
- 点击区域应该是整个卡片

### 11.2 FileDropzone

用途：

- 所有选择文件的工具共用

必须支持：

- 点击选择文件
- 拖拽文件
- 显示支持格式
- 显示本地处理说明
- 文件格式不符合时提示

### 11.3 LocalProcessingNotice

用途：

- 展示本地处理说明

要求：

- 靠近文件选择区域
- 文案支持中英文
- 只在确实本地处理的工具里使用

### 11.4 ResultList

用途：

- 展示处理后的文件

必须支持：

- 文件名
- 原始大小
- 新大小
- 节省比例
- 下载按钮
- 移动端卡片展示

## 12. 移动端规范

移动端必须优先保证能完成操作。

要求：

- 导航不要挤压内容
- 工具卡片单列
- 上传区域不小于 `240px`
- 表格在移动端切换为卡片
- 按钮宽度适合手指点击
- 文案不能溢出容器

当前原型已经有移动端适配，后续正式开发要保留这个方向。

## 13. SEO 规范

每个正式工具页必须有独立 SEO 信息。

至少包括：

- 页面标题
- 页面描述
- 一个 H1
- 工具说明
- 相关工具链接

图片压缩页英文标题示例：

```text
Compress Image Online - Reduce Image Size in Browser
```

图片压缩页中文标题示例：

```text
在线压缩图片 - 在浏览器中减小图片体积
```

### 14.1 原型验证

- 首页是否显示

正式项目开发后至少验证：

- `npm run dev` 能启动
- 首页能访问

- 中英文切换可用
- 图片工具真实处理可用
